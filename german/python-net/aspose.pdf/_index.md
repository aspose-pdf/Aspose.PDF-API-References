| [PdfASymbolicFontEncodingStrategy](/pdf/python-net/aspose.pdf/pdfasymbolicfontencodingstrategy/) | Diese Klasse beschreibt Regeln, die verwendet werden können, um den Prozess des Kopierens von Codierungsdaten für Fälle zu optimieren<br/>            wenn eine TrueType‑Symbolschrift mehr als eine Codierung hat.<br/>            Einige PDF‑Dokumente können nach der Konvertierung in das PDF/A‑Format den Fehler <br/>            \"More than one encoding in symbolic TrueType font's cmap\" erhalten. <br/>            Was ist die Ursache dieses Fehlers? Alle TrueType‑Symbolschriften besitzen eine spezielle Tabelle \"cmap\"<br/>            in ihren internen Daten. Diese Tabelle ordnet Zeichen­codes Glyphen‑Indizes zu. <br/>            Und diese Tabelle kann verschiedene Codierungs‑Untertabelle enthalten, die<br/>            die verwendeten Codierungen beschreiben. Siehe erweiterte Informationen zu cmap‑Tabellen unter<br/>            https://developer.apple.com/fonts/TrueType-Reference-Manual/RM06/Chap6cmap.html.<br/>            Normalerweise enthält die cmap‑Tabelle mehrere Codierungs‑Untertabelle, aber der PDF/A‑Standard verlangt,<br/>            dass nur eine Codierungs‑Untertabelle (3,0) für diese Schrift im PDF/A‑Dokument belassen wird. <br/>            Und die zentrale Frage hier – welche Daten müssen aus den anderen Untertabellen genommen werden, um sie in die<br/>            Ziel‑Codierungstabelle (3,0) zu kopieren? Die Mehrheit der Schriften hat 'wohlgeformte' cmap‑Tabellen, bei denen<br/>            jede Codierungs‑Untertabelle vollständig mit einer anderen Untertabelle konsistent ist. Einige Schriften<br/>            besitzen jedoch cmap‑Tabellen mit Kollisionen – zum Beispiel hat eine Untertabelle den Glyphen‑Index <br/>            100 für Unicode 100, während eine andere Untertabelle den Glyphen‑Index 200 für denselben Unicode 100 hat.<br/>            Zur Lösung dieses Problems ist eine spezielle Strategie erforderlich. <br/>            Standardmäßig wird folgende Strategie verwendet: <br/>            Es wird nach der mac‑Untertabelle (1,0) gesucht. Wird diese Tabelle gefunden, werden nur deren Daten verwendet, um die Ziel‑Codierungstabelle (3,0) zu füllen. Wird die mac‑Untertabelle nicht gefunden, werden alle Untertabellen außer (3,0) iteriert <br/>            und deren Daten in die Ziel‑(3,0)‑Untertabelle kopiert. Außerdem wird die Zuordnung für jedes Unicode (Unicode, Glyphen‑Index)<br/>            nur dann in die Zieltabelle kopiert, wenn die Zieltabelle dieses Unicode momentan nicht enthält. <br/>            So wird zum Beispiel, wenn die erste Untertabelle den Glyphen‑Index 100 für Unicode 100 hat und die nächste Untertabelle den Glyphen‑Index 200 für denselben Unicode 100, nur das Datum aus der ersten Untertabelle (Unicode=100, Glyphen‑Index = 100) kopiert. <br/>            Jede vorherige Untertabelle hat also Vorrang vor der nächsten. <br/>            Eigenschaften dieser Klasse [PdfASymbolicFontEncodingStrategy](/pdf/python-net/aspose.pdf/pdfasymbolicfontencodingstrategy/) helfen, das Standardverhalten anzupassen. <br/>            Wenn die Eigenschaft [preferred_cmap_encoding_table](/pdf/python-net/aspose.pdf/pdfasymbolicfontencodingstrategy/) vom Typ [CMapEncodingTableType](/pdf/python-net/aspose.pdf.pdfasymbolicfontencodingstrategy.queueitem/cmapencodingtabletype/)<br/>            gesetzt ist, wird die entsprechende Untertabelle mit Vorrang vor der mac‑Untertabelle (1,0) verwendet. Der Wert 'MacTable' aus<br/>            der Aufzählung [CMapEncodingTableType](/pdf/python-net/aspose.pdf.pdfasymbolicfontencodingstrategy.queueitem/cmapencodingtabletype/) hat in diesem Fall keine Bedeutung, da er <br/>            auf dieselbe mac‑Untertabelle (1,0) verweist, die standardmäßig verwendet wird. <br/>            Die Eigenschaft [None](/pdf/python-net/aspose.pdf/pdfasymbolicfontencodingstrategy/) verwirft alle Prioritäten für jede Untertabelle.<br/>            Ist diese Eigenschaft gesetzt, werden nur Untertabellen aus der deklarierten Warteschlange in der angegebenen Reihenfolge verwendet.<br/>            Werden die angegebenen Untertabellen nicht gefunden, wird die Standard‑Iteration aller Untertabellen und die oben beschriebene Kopier‑Strategie verwendet.<br/>            Das Objekt [QueueItem](/pdf/python-net/aspose.pdf.pdfasymbolicfontencodingstrategy/queueitem/) gibt die zu verwendende Codierungs‑Untertabelle an. Diese Untertabelle kann<br/>            über eine Kombination von Mitgliedern (PlatformID, PlatformSpecificId) oder über die Aufzählung [CMapEncodingTableType](/pdf/python-net/aspose.pdf.pdfasymbolicfontencodingstrategy.queueitem/cmapencodingtabletype/)<br/>            festgelegt werden. |
